# 日报整理

## 边界

- 只在用户明确要求记录或汇总日报时运行；不能在每次对话结束时自动写入。
- 只记录当前对话中有完成证据的事项。计划、讨论结论、尝试失败和待办不算完成。
- **只记录落到代码上的产出**。需求收集、资料整理、调研这类开工前的准备工作不进日报。
  每条只写概念，不写实现。纯视觉微调不记。
- 日志默认按天保存到 `~/.specweaver/daily-logs/YYYY-MM-DD.md`；设置
  `SPECWEAVER_HOME` 时改用该目录下的 `daily-logs/`。
- 只保存项目名称、需求全称和概念条目，不保存对话全文、私有链接、Cookie、密码、Token、账号或登录响应。
- 记录动作只写本机共享日志，不修改当前项目代码，不执行 Git 提交或外部发布。

## 判断用户意图

按用户当前表达选择一种模式：

1. “整理一下日报”“记录这次完成内容”“加入日报”：执行“记录本次任务”。
2. “整理今天日报”“汇总今日工作”“生成今天的日报”：执行“汇总当天日报”。
3. 用户同时要求先记录本次任务再汇总今天：先记录，再汇总。
4. 「四件套」不是本 Skill 的入口。由 `spec-four-piece` 转入时，只执行「记录本次任务」。

无法判断目标日期时使用本机当天日期。用户明确指定日期时使用该日期，不擅自跨天合并。

## 格式

成品只有一种，由脚本生成。汇总时原样转述，不要改编号、不要加空格、不要换排版、不要再拆 `1.1.1`：

```text
项目：项目名称
1.需求全称
1.1 概念
1.2 概念

项目：另一个项目
1.需求全称
1.1 概念
```

`1.需求全称` 的点号后面没有空格。有空格会被聊天工具当成 Markdown 列表重新编号。`1.1` 后面有一个空格。

编号由脚本按当天已有记录现算。写入时不要自己编 `1.`、`1.1`。

## 写什么

需求名称用任务全称，原样保留版本号和后半句，不缩成几个字。

正例：`【13.2】PC端AI比价推广功能支持快速录入收寄件城市地址，自动识别比价`

反例：`AI比价`

没有任务标题时用能概括这批改动的功能名，并先问用户。不要用仓库目录名。

每条 `--point` 只写概念：这次交付了什么能力或规则，同事不看代码也能复述。方案和改动用这句话带上，不要拆成下一层。

正例：`扫码开门必须先拿到定位，没拿到就不请求开门。`

反例：`新增 ensureLocation，getLocation 类型为 gcj02，失败时调用 openAppAuthorizeSetting。`

不写实现。下面这些出现在句子里，就是写错了，改写成概念；整条都是这些，就不要记：

- 像素、字号、色值、间距、列宽、对齐
- 组件名、函数名、文件名、接口路径、字段名、枚举值
- mock、样式抽离、文案字数、弹窗高度

纯视觉微调（改个 px、换个颜色、调列宽）整段不记。当天只有这类改动时不调用脚本，向用户说明没记。

## 记录本次任务

1. 按“对话中明确的产品或项目名 → 当前任务所在目录 → 仓库名”的优先级确定项目
   名称。多项目仓库不能直接使用仓库名；无法唯一判断时先询问用户。
2. 需求名称用任务全称，规则见「写什么」。一次对话涉及多个需求时按需求分多次执行脚本，
   不要塞进同一个需求，也不要把标题缩短后再写入。
3. 提取当前对话中已经完成并经过验证的概念，每个概念一条 `--point`。
   写之前先丢掉像素、色值、组件名、字段名、接口路径这类实现。只剩视觉微调时不要调用脚本。
4. **准备性工作不写**：需求收集、资料整理、蓝湖与 Eolink 取数、调研结论、
   生成 requirement.md、读代码确认可行性——这些是开工前的准备，不是当天产出。
5. 同一需求下字面完全相同的概念不重复写入。不要记录执行过程或命令流水。
6. 检查内容中没有认证信息、私有链接和原始响应。
7. 从插件根目录执行：

```bash
python3 skills/daily-report/scripts/daily_log.py add \
  --project "<项目名称>" \
  --requirement "<需求全称>" \
  --point "<概念 1>" \
  --point "<概念 2>"
```

如果当前工作目录不是插件根目录，使用脚本的绝对路径。脚本每天创建一个 Markdown
文件，按“项目 → 需求”合并，同一需求下完全相同的概念不会重复写入。

8. 向用户报告实际写入的项目、需求全称、新增概念数量，以及 md 和同目录 txt 的绝对路径。没有可记的概念时不写文件，说明原因。

## 汇总当天日报

1. 执行：

```bash
python3 skills/daily-report/scripts/daily_log.py show
```

指定日期时追加 `--date YYYY-MM-DD`。脚本读取当天的 Markdown，并把成品写到同目录的
`YYYY-MM-DD.txt`。记录条目时这个 txt 也会一起更新。

2. **脚本的标准输出已经是可直接发送的成品，原样转述，不要改写、重新排版或补充**。
   它和同目录 txt 的内容一致。成品长什么样见上面「格式」。编号由脚本按存储顺序生成。
   日报正文只有这些内容，文件路径这类提示走标准错误，不要带进去。

3. 不把汇总结果再次追加到共享日志。当天没有记录时明确说明，不虚构内容。

## 完成检查

- 日期、项目名称和需求名称明确；
- 每一项都能在当前对话或当天共享日志中找到完成证据；
- 需求名称是任务全称，没有被缩短；
- 每条都是概念，没有像素、色值、组件名、字段名、接口路径这类实现，也没有混入需求收集和调研；
- 没有混入进行中事项、问题、明日计划或敏感信息；
- 记录模式已确认文件真实写入，汇总模式已覆盖当天全部项目且输出原样来自脚本；
- 明确提醒边界：没有主动说“整理一下日报”的任务不会自动进入日志。
